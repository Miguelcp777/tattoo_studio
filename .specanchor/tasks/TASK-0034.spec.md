# Task: Proposed size by default, relevant references, and a clear next step

## 1. Problem / requested change (user, 2026-09-27, after trying the app)

1. The size the agent recommends is not set by default.
2. Reference photos are wrong for the theme, or none are added.
3. The flow is confusing: you cannot tell what is missing, what to do, or what comes next.

## 2. Current behavior (evidence)

- The architect's size is discarded (TASK-0033 rule) and nothing proposes a size from the zone
  unless the client writes a qualitative word, so the brief always reports "Falta el tamaño".
  OBSERVED, `architect.ts`, `researcher.ts`.
- Live survey of six typical ideas (scratch run, 2026-09-27): the scout keeps the first Commons
  hit without checking it — "Red Moon logo" for a howling wolf, an Adenium flower for a rose, a
  London panorama for an old map, "Caliber watercolor" for a hummingbird; the Barça crest and a
  golden retriever found nothing. The Sonnet planner writes queries with filler words ("photo",
  "Wikimedia Commons", "high resolution") that full-text search does not match. Non-free logos
  are not on Commons at all. VERIFIED (live run).
- Generation needs seven conditions (brief complete, references, no missing entity reference,
  panel saved, brief accepted, adult, consent, references reviewed) and the disabled button names
  none of them. The chat's closing message says "revisa los valores del brief" when the size is
  what is missing. Every planned query that finds nothing blocks generation, even for a generic
  motif. OBSERVED, `page.tsx`, `orchestrator.ts`.

## 3. Desired behavior

- **Size (INTENT, user):** once a zone is known and the client has not stated a size, the studio
  proposes one: the architect's recommendation scaled down to fit the zone's reference span, or a
  medium fraction of the zone when there is none. It is marked as a proposal (`size.proposed`),
  shown as "propuesto por nosotros" in the brief and pre-filled in the panel; an explicit client
  value always wins; a proposal is re-made when the zone changes. This amends TASK-0033's "the
  architect never sets the size" at the user's request, within ADR-0010 (proposed from the zone
  and the idea, shown rather than applied silently).
- **References:** the planner writes 1–3 short queries of concrete nouns, marks which are
  *essential* (a specific emblem, flag, landmark, artwork or logo whose exact look matters) and
  gives each a Spanish label. The scout gathers several Commons candidates per query and a Claude
  Sonnet **vision check** keeps only images that actually depict the request. If that check fails,
  none are kept (an irrelevant reference would steer the design wrong). Only a missing *essential*
  reference blocks generation, and the message names it in Spanish and says to attach it.
- **Guidance:** the chat's closing message states what was proposed and the one next action. The
  panel shows a "Siguiente paso" banner and, under the Generate button, the list of what is still
  missing, each linking to its section.
- Scout and architect run in parallel, so the extra check does not lengthen the turn.

## 4. Scope / 5. Out of scope

In: `packages/consultation` (scout, planner, judge, orchestrator, architect, master prompt,
types), `apps/web` (page guidance, `lib/steps.ts`, composition). Out: an open-web image search
provider (logos stay "attach it yourself"), redesigning the page layout.

- TASK-0034/REQ-002: Planner queries are short concrete nouns with `essential` and a Spanish label.
- TASK-0034/REQ-003: With a judge, only candidates the vision check accepts become references; a
