# Task: Daily spending limits before any paid call (audit SEG-02)

## 1. Problem / requested change

Audit finding SEG-02: authentication and one-job concurrency, but no daily budget per account; the
consultation also spends (Claude, the reference search) before the queue. The audit asked for a
reservation before each paid operation, per-account quotas and a global limit, including the
consultation and the search, answering 429 with an explanation before calling the provider and
counting a retry once. Evidence: OBSERVED in `generate/route.ts` and `jobs/queue.py`.

## 2. Current behavior

`JobQueue.enqueue` refused a second active job per account and more than eight in all; nothing
counted per day.

## 3. Requirements

- **REQ-001** — Designs and redraws: per account per UTC day (`TATTOO_DAILY_DESIGNS`, default 20)
  and for the studio (`TATTOO_DAILY_DESIGNS_TOTAL`, 300), checked in `enqueue` before the insert. A
  repeated idempotency key returns the stored job and is not counted again. Re-placements through
  the coverage controls (`mode: placement`, no attached photos) and kept camera photos are not
  billable (`jobs.billable`).
- **REQ-002** — Paid consultation turns (a message, a reference search) per account per UTC day
  (`TATTOO_DAILY_TURNS`, 100) in the worker's `TurnLedger`, reserved by the web through
  `POST /studio/quota/turns` with an id per turn (counted once), only when the consultation calls
  paid models, before it does.
- **REQ-003** — A reached limit answers 429 with a plain message (designs, studio, turns).

## 4. Acceptance criteria

- **AC-001** — Worker tests: the account limit with a repeated key and another account; the global
  limit; billability; the turn ledger with a repeated id and a new day; the routes answer 429.
- **AC-002** — Web: `reserveTurn` calls the worker and surfaces 429 with paid models, and nothing
  without them.
