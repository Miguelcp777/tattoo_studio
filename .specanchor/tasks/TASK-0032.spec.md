# Task: Model-backed agent triad and a worker LangGraph creation pipeline with the AI blend

## 1. Problem / requested change

Turn the existing agent shape into a working multi-agent system:

1. A **prompt architect** that improves the client's idea into a detailed, generation-ready brief.
2. A **visual scout** that finds reference imagery when the client gave none or too few.
3. A **visual creator** that produces the on-body mockup and the thermal stencil from the brief,
   the scouted references and the client's own references.
4. An **orchestrator** coordinating them effectively.

The creator must integrate the design into the photograph with an AI blend (the client's explicit
decision), which requires activating the pass ADR-0002 designed and ADR-0007 froze.

## 2. Current behavior

- `packages/consultation/src/agents/` has the four roles, but the scout and architect are
  deterministic (regex extraction in `researcher.ts`; Wikimedia Commons queries in
  `image-scout.ts`), and `creator.ts` throws by design (ARCH-INV-001). Source: OBSERVED, HEAD
  `8896fee`.
- Reasoning uses OpenAI GPT-6 Astra via `providers/openai-astra.ts` (`ConsultationProvider`).
  Source: OBSERVED.
- The creation pipeline is inlined in `services/worker/app/studio.py::Studio.generate`: analyse
  references → native/colour artwork via `generation` → centerline stencil trace → **geometric
  multiply** composite only. There is no generative pass after placement (ADR-0007). Source:
  OBSERVED, `app/studio.py`.
- `generation` image-to-image / inpaint methods exist but are unreachable: they require a
  `SafetyClearance`, which is uninstantiable without a screened photo. Source: OBSERVED,
  `generation.spec.md`, `safety.spec.md`.

## 3. Desired behavior

- Architect runs on Claude Opus 5.5; scout runs on Claude Sonnet 5; both behind the existing
  `ConsultationProvider` seam, selected by configuration (ADR-0015). Neither generates imagery.
- Scout searches licensed sources first (Commons) and falls back to a bounded open-web image search
  only when licensed sources return nothing; every candidate passes `safety` screening before it
  can become a reference.
- A new `orchestration` module hosts a LangGraph graph that sequences the creator pipeline inside a
  `jobs` job, calling image models only through `generation` and moderation only through `safety`
  (no new egress).
- The mockup runs the constrained AI blend on the screened body photo (ADR-0016), guarded by the
  geometry check; on tolerance failure the render fails honestly. The stencil stays native
  line-art centerline vector (ADR-0003), never derived from the blended render.

## 4. Scope

- New module `services/worker/orchestration/` and its spec; `module-map.json` + `spec-index.md`.
- LangGraph graph refactor of `Studio.generate` sequencing into named, testable nodes
  (behaviour-preserving first), then the `ai_blend` + `geometry_check` + `output_gate` additions.
- Claude provider for `consultation`; Opus/Sonnet role assignment; scout open-web fallback + safety
  screening of scouted candidates.
- Enabling `generation`'s image-to-image / inpaint path through a real `SafetyClearance` for the
  blend, with provider eligibility (no-training) enforced.

## 5. Out of scope

  this task consumes their result and keeps geometric-only as the fallback until they land.
- Legal review, DPIA, retention window and residency (ADR-0006 pre-launch blockers) — tracked, not
  resolved here.
- Any change to the stencil geometry, the 1:1 print path, or the contracts schemas.
- Living-artist mimicry policy (unchanged; PROD-INV-004).

## 9. Design approach

Two-tier orchestration per ADR-0015: interactive TS triad (architect Opus, scout Sonnet, existing
`OrchestratorAgent`) and a worker LangGraph pipeline in `orchestration`. `Studio.generate` becomes a
thin caller that builds and invokes the graph. Blend activation per ADR-0016, gated on TASK-0008.

## 10. API / data / UI impact

- No contract schema change (`tattoo-brief`, `studio-job`, `studio-status` unchanged).
- New worker configuration: Claude keys/models for `consultation`, blend-provider selection and its
  no-training flag for `generation`. Secrets stay in environment config; specs record paths only.
- Web surface unchanged except copy already required by PROD-INV-005 (illustrative labelling).

## 11. Migration and backward compatibility

The node refactor is behaviour-preserving (AC-002). The blend is additive and defaults off until a
provider passes TASK-0008; existing geometric-only behaviour remains the fallback, so no existing
session output regresses.

## 12. Test plan

Consultation: recorded-fixture Claude provider reaches a valid brief; scout fallback + safety
rejection. Orchestration: parity suite vs current studio outputs; graph node unit tests. Mockup:
geometry-tolerance corpus tests; clearance-required and provider-eligibility tests in `generation`;
stencil-independence test. Safety: output-gate-before-store test. Run TS and Python suites
separately from the guard (see README commands).

## 13. Risks and rollback

- **Geometry drift** (design redrawn): mitigated by the mandatory geometry check; render fails
  rather than shipping. Largest risk in the project (ADR-0002).
- **Photo exposure**: mitigated by clearance binding, no-training provider eligibility, output gate,
  and the geometric-only fallback. Legal/DPIA remain pre-launch blockers (ADR-0006).
- **Vendor divergence** (Flux vs GPT-Image): isolated behind the `generation` registry (ADR-0009).
- Rollback: disable the blend provider; the pipeline reverts to geometric-only with no data change.

graph (`graph.py`) wiring the ADR-0015 node order (`pipeline.py`, `nodes.py`, `state.py`), driven by

approved and installed; the wiring in `pipeline.py` does not change.

a per-call `_StudioGenerationDeps` adapter that reproduces the previous inline behaviour — full
worker suite `365 passed`, `mypy .` and ruff clean (REQ-002). The creator's finish intent
