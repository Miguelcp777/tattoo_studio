# Task: Measure the queue before scaling it (audit REN-01)

## 1. Problem / requested change

Audit REN-01: one serial executor, at most eight active jobs; a slow generation delays everyone.
The audit's first step: measure duration and queue wait (p50/p95) before scaling; then leases and
idempotency over a shared queue. Evidence: OBSERVED in `jobs/queue.py` and the compose file.

## 2. Current behavior

The panel reported generation duration (avg, p50, p95) but not how long jobs waited to start.

## 3. Requirements

- **REQ-001** — Each job event records `detail.waitMs` (start minus creation); the overview reports
  `totals.waitMs` (avg, p50, p95) over every job, and the panel shows «Espera en cola».
- **REQ-002** — The scaling guarantees in place are kept and stated: one worker replica (pinned in
  the compose file and asserted by a test), idempotency keys returning the stored job, interrupted
  jobs failed rather than recharged. Leases over a shared queue are deferred until the measurements
  show the need.

## 4. Acceptance criteria

- **AC-001** — `test_a_job_records_how_long_it_waited`; `test_the_queue_wait_is_reported_for_every_job`.
- **AC-002** — Web typecheck of the panel's optional `waitMs`.
