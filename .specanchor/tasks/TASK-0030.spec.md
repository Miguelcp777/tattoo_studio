# Task: A catalogue pick must survive being generated from

## 1. Problem / requested change

Owner report with a screenshot: choosing a style variant and pressing generate returned
*"No se pudo completar la solicitud"*. Defect introduced by TASK-0028.

## 2. Current behavior

- `offerAsReference` writes `source: "/style-library/<style>/<variant>.webp"`, a web-relative
  path. Evidence: OBSERVED.
- `POST /api/generate` uploads any reference lacking an `assetId` via `referenceBytes`, which
  begins `new URL(source)`. With a relative path and no base that throws `TypeError`, an
  unexpected error rather than a typed one, so the client saw a generic 500. Evidence: VERIFIED,
  `POST /api/generate 500` in the dev log with no corresponding worker request.
- The reference card displayed `label`, which TASK-0028 set to the English prompt text, to a
  Spanish-speaking client. Evidence: OBSERVED in the owner's screenshot.

## 3. Desired behavior

A catalogue pick reaches the worker like any other reference, and the card names it in Spanish.

## 4. Scope

`apps/web/src/lib/studio-server.ts`, `apps/web/src/app/api/generate/route.ts`,
`packages/consultation/src/agents/style-library.ts`, and a new test file.

## 5. Out of scope

`referenceBytes` and its allowlist. Anything in the skin-finish work, which is TASK-0031.

## 6. Affected anchors

TASK-0028 (defect), SEC-INV-008, the egress allowlist in `referenceBytes`.

## 7. Requirements

- **REQ-001** — A catalogue image is read from disk, not fetched.
- **REQ-002** — Only a source that resolves in the catalogue is served; the path is rebuilt from
  what the catalogue returns, never from what arrived.
- **REQ-003** — `referenceBytes` and its allowlist are unchanged.
- **REQ-004** — The reference card names the pick in Spanish.

## 8. Acceptance criteria

- **AC-001** (REQ-001) — `catalogueBytes` returns the bytes of a real catalogue image.
- **AC-002** (REQ-002) — A fabricated style or variant is refused; four traversal attempts are
  refused before reaching the filesystem.
- **AC-003** (REQ-003) — A test asserts `referenceBytes` still refuses a non-allowlisted host and
  a non-HTTPS scheme.
- **AC-004** (REQ-004) — The reference's `label` is the Spanish style and variant name.

## 9. Design approach

The catalogue is our own static asset, so it is read from disk. The tempting fix — adding our own
origin to `referenceBytes`' allowlist — was rejected: that allowlist is the project's SSRF
control, and widening it to read a file already on disk is a poor trade.

## 10. API / data / UI impact

None externally. One new server-side helper.

## 11. Migration and backward compatibility

A session holding a catalogue pick from before this fix now generates successfully.

## 12. Test plan

Five tests: a real read, two refusal cases, four traversal attempts, and one asserting the
external allowlist is intact.

## 13. Risks and rollback

Reading from disk by a client-supplied string is the risk. Mitigated by resolving the identifier
through the catalogue first, so the path is never taken from the request.

## 14. Implementation checklist

- [x] `catalogueBytes` and `isCatalogueSource` in `studio-server.ts`.
- [x] The generate route picks the reader per reference.
- [x] `label` is the Spanish name.
- [x] `apps/web/src/lib/catalogue-bytes.test.ts`, 5 tests.
- [x] Specs updated: `web`, `consultation`.

## 15. Decision log

- **DEC-001** — The allowlist was not widened. It is the SSRF control, and the file was already
  on disk.
- **DEC-002** — Traversal is prevented by construction rather than by sanitising the input: the
  identifier must resolve in the catalogue, and the path is rebuilt from the resolved entry.
