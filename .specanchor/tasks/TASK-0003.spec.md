# Task: Consultation state machine and OpenAI GPT-6 Astra reasoning engine

## 1. Problem / requested change

Users arrive with vague tattoo ideas, style preferences, and reference images or photos (sketches,
existing tattoos, motifs). The system needs an interactive consultation agent that acts as an
experienced tattoo artist: interviewing the user, examining uploaded visual references, mapping
preferences onto the closed curated style vocabulary, and outputting a validated `TattooBrief`.

The engine must use **OpenAI GPT-6 Astra** (`gpt-6-astra`) as its reasoning and multimodal vision
foundation, while strictly adhering to `CONSULT-INV-001` (consultation only produces briefs, never
generates imagery) and `PROD-INV-004` (never imitates the style of named living artists).

## 2. Current behavior

- `TattooBrief` 1.0.0 contract exists and is verified in both runtimes (TASK-0002).
- `consultation.spec.md` exists in draft status naming Claude for extraction.
- `packages/consultation/` does not exist yet (OBSERVED).
- The baseline spec check reports 0 unmapped files.

## 3. Desired behavior

- An interactive consultation state machine in `packages/consultation` that guides users turn-by-turn.
- User turns support multimodal input: text message plus optional reference images (URLs or base64 data).
- The reasoning engine uses OpenAI GPT-6 Astra (`gpt-6-astra`) with tool-calling structured output to extract brief fields.
- A deterministic `FixtureConsultationProvider` is provided for offline testing and CI runs without live credentials.
- When all required slots are filled and valid, `brief(state)` returns a canonical, validated `TattooBrief`.
- Requests to imitate named living artists are rejected with an explanation and steered toward the underlying generic style.
