# Task: An essential reference that cannot be found is never a dead end

## 1. Problem / requested change

On a phone the owner asked for the Ramones logo. The planner marked "el logo de la banda Ramones"
essential, nothing licensed was found, and step 3 blocked: "no he podido avanzar". The disabled
«Continuar sin referencias» did not look disabled, and the notice read «una imagen de el logo».
Evidence: INTENT, OBSERVED (screenshot).

## 2. Current behavior

TASK-0034 made a missing essential reference block generation until one was found or supplied; the
wizard's continue button was disabled with no other way on. Evidence: OBSERVED.

## 3. Requirements

- **REQ-001** — With an essential reference missing, step 3 leads with adding the image, and also
  offers searching again and going on without it.
- **REQ-002** — Going on without it asks first, saying the design will be an interpretation; once
  accepted the server stops requiring it for this idea (and requires it again for a new idea).
- **REQ-003** — Disabled answers look disabled; the notice contracts «de el» into «del».

## 4. Acceptance criteria

- **AC-001** — `architect.test.ts`: an essential miss blocks; with `waivedReferences` the phase is
  ready and the plan still names what was essential.
- **AC-002** — `consultation/route.test.ts`: `waive_references` records the choice on the session.
- **AC-003** — `master-prompt.test.ts`: `ofSpanish` contracts «el» and leaves «la» and «elefante».
- **AC-004** — Live at 375 px: the buttons and notice of step 3, one warning pop-up, then the summary.
