# Task: attach reference photos to a change request, and keep a resized size across edits

## 1. Request (user, 2026-09-27)

"Quiero poder añadir fotos una vez ha creado el primer mockup, estilo: quiero una virgen como en la
foto adjunta." (INTENT)

## 2. Current behavior (evidence)

- The change form in the preview accepts text only; `edit` in `studio-job` carries
  `parentJobId`, `instruction`, `coverage`, `mode`. A change reuses the parent's references and
  cannot add any. OBSERVED, `TattooPreviewModal.tsx`, `studio-job.schema.json`.
- The live session shows the need: the client asked "busca otra imagen de la Mare de Déu". An
  artwork edit cannot search; it redrew with the same references. VERIFIED (worker `jobs.sqlite`).
- Found in the same session: "que ocupe todo el gemelo" resized 140 × 260 → 140 × 380 mm, and the
  next edit of that version came back at 140 × 260. A child job is built from the parent's stored
  *payload*, which predates the resize; the resized millimetres live only in the parent's
  *result*. VERIFIED (job lineage in `jobs.sqlite`; `router.submit` in `app/studio.py`).

## 3. Desired behavior

- The change form offers "Adjuntar foto de referencia" (optional, up to three). Each photo goes
  through the same worker ingestion as any reference — sanitize, EXIF strip, moderation gate,
  adult + consent — and is **not** added to the consultation, so an accepted brief is not
  reopened. A rejected photo shows its reason inside the dialog.
- `edit.referenceIds` (contract, 1–3 owned asset IDs). The worker checks ownership, puts them
  first in the design's references (cap 5) so later versions keep them, sends them to the image
  edit right after the accepted master, and tells the model that those images are what the
  request points at, to be redrawn in the artwork's style. Their vision analysis is appended to the
  traceability text. A change with photos always redraws: a whole-zone phrase in the same
  sentence does not short-circuit to a placement-only reposition.
- An edit inherits its parent's millimetres (from the parent's result), so a resized version
  stays resized.

## 4. Requirements / acceptance

- REQ-001 / AC-001: contract accepts `edit.referenceIds` (1–3) in `studio-job` and `studio-status`;
  fixtures `edit-with-references` (valid), `edit-too-many-references` (invalid).
- REQ-002 / AC-002: worker test — attached photo is first after the master, `attached == 1`, the
  parent reference follows, analysis records it, `result.edit` echoes it; an unowned photo → 422.
- REQ-003 / AC-003: edit prompt names "image 2" / "images 2 to N" only when photos are attached.
- REQ-004 / AC-004: BFF `purpose: 'edit'` upload forwards only image + consent and does not touch

- REQ-005 / AC-005: worker test — an edit of a zone-resized version keeps the resized size; the
  test fails with the fix removed.
- AC-006: live check in the running app (upload a photo in the change form and create a version).
