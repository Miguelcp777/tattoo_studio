# Task (light): a misspelt whole-zone request left the tattoo the same size

## Problem (user, 2026-09-27)

After a first proposal on the calf (140 × 260 mm) the client asked the preview to make the tattoo
fill the whole leg; the new version stayed the same size.

## Current behavior (evidence)

- The stored edit instruction was "que ocupe todo el gemlo". VERIFIED (worker `jobs.sqlite`,
  latest job, same `size` 140 × 260 mm as its parent).
- `whole_zone_intent` required an exact zone noun with a quantifier, a verb with "de arriba a
  abajo", or joint-to-joint. The misspelling "gemlo" matched none, so `coverage_request` returned
  `None` and the request ran as an AI artwork edit at the parent's millimetres. OBSERVED,
  `mockup/placement.py`.

## Change

- A zone noun within one slip of a known one (`difflib`, cutoff 0.8, words of five letters or
  more) counts as a zone, still only together with a quantifier.
- "<verb> todo/toda/entero… el|la|mi… <noun>" is a whole-zone request whatever the noun is
  ("todo el modelo"), unless that noun is an artwork word (escudo, lobo, flor…), so
  "que el escudo cubra todo el lobo" stays an artwork edit.
- Negation and the existing phrases keep their meaning.

## Acceptance

- AC-001: `mockup/tests/test_coverage.py` — the live phrase, "atebrazo", "todo el modelo" resolve
  to `Coverage("full", True)`; "rellena todo de color", "que el escudo cubra todo el lobo",
  "pon todo el texto en negro" resolve to `None`; all earlier cases unchanged.
- AC-002: worker `pytest mockup app` 110 passed; ruff, format and mypy clean on the touched file.
  VERIFIED 2026-09-27.
