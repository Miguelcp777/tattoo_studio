# Task: Guide the client through the design, and stop demanding a size

## 1. Problem / requested change

Owner feedback, 2026-09-22: the flow should think about a first-time client and walk them through
it, showing which steps are done and which remain; the size should be whatever the design process
interprets when the client does not state one; and the interface is visually unbalanced, needs too
much scrolling on one side, and has no background suited to a tattoo studio. Implements ADR-0010.

## 2. Current behavior

Measured on the running application at 1440x900 (VERIFIED, 2026-09-22):

- Preferences panel **1027 px tall in a 900 px viewport**; document 1151 px, so 251 px of scroll
  and the primary action below the fold. Below 1024 px the layout collapses to one column.
- `body` `background-image: none`. Flat colour only.
- No progress indication anywhere: every field is presented at once with nothing marking what is
  complete.
- `orchestrator.ts` pushed `'medidas en mm'` into `missingFields`, while `missingPreferences` —
  the list that actually gates completion — never included size, and
  `providers/openai-astra.ts:27` already instructs the model to recommend a size per anatomy.
  Evidence: OBSERVED.
- CONSULT-INV-004 required asking for the size explicitly, contradicting that shipped behaviour.

## 3. Desired behavior

A persistent rail names every step and its state. Size is proposed, shown and editable, never
reported as outstanding. The panel cannot outgrow the viewport. The page reads as a studio.

## 4. Scope

`apps/web/src/components/StepFlow.tsx` (new), `apps/web/src/lib/steps.ts` (new) and its tests,
`apps/web/src/app/page.tsx`, `apps/web/src/app/globals.css`,
`packages/consultation/src/agents/orchestrator.ts`.

## 5. Out of scope

Gating the panel's fields by step (deferred in ADR-0010), any change to `contracts`, the worker,
or how a brief is validated. No new dependency, no image asset, no DOM test environment.

## 6. Affected anchors

ADR-0010 (implements), CONSULT-INV-004 (amended), WEB-INV-001, ADR-0008 (supplies the anatomical
basis that makes proposing a size defensible).

## 7. Requirements

- **REQ-001** — A rail names each step and marks it done, current or pending, says how many are
  complete, and marks optional steps as optional.
- **REQ-002** — Step state is derived from the same values the panel gates on, in a pure function
  testable without a DOM. The rail holds no rule of its own (WEB-INV-001).
- **REQ-003** — Size is not reported as a missing client answer. The millimetre fields are marked
  optional and show any proposed size as placeholder. An explicit value still wins.
- **REQ-004** — Above 1024 px the preferences panel is sticky with its own scroll and cannot
  exceed the viewport height.
- **REQ-005** — The page carries a layered studio background authored in CSS, with no image asset
  and no new dependency.

## 8. Acceptance criteria

- **AC-001** (REQ-001) — The rail renders five steps with the expected labels and states, and
  reports the completed count. Verified on the running page.
- **AC-002** (REQ-002) — `buildSteps` is unit-tested across the progression, including that the
  design step is never current before the brief is complete, and that age alone does not clear
  permissions.
- **AC-003** (REQ-003) — References are marked optional and the design step becomes reachable with
  zero references; `'medidas en mm'` no longer appears in `missingFields`; a proposed size is shown
  in the rail and as placeholder.
- **AC-004** (REQ-004) — Measured on the running page, the panel is `position: sticky` with
  `overflow-y: auto` and its height is below the viewport height.
- **AC-005** (REQ-005) — `body` reports multiple background layers where it previously reported
  `none`.

## 9. Design approach

See ADR-0010. The only structural choice worth recording is that step derivation lives in
`lib/steps.ts` rather than in the component: it is the part that can be wrong, and putting it
there makes it testable in the existing `node` environment instead of forcing a DOM runtime into
the project for this change.

## 10. API / data / UI impact

UI only. No contract, schema or route change. `missingFields` no longer carries a size entry,
which is a visible behaviour change and the point of REQ-003.

## 11. Migration and backward compatibility

None. An explicit size entered by the client behaves exactly as before.

## 12. Test plan

Unit tests over `buildSteps`. Layout and background assertions are measurements against the
running page, recorded in the evidence ledger, because they are properties of rendered CSS that
the `node` test environment cannot observe.

## 13. Risks and rollback

The rail is derived state and will report confidently if its conditions drift from the panel's.
Mitigated by deriving both from the same values and by AC-002. Rollback is removing the rail;
nothing else depends on it.

## 14. Implementation checklist

- [x] `components/StepFlow.tsx`: presentation only, keyboard reachable, state announced.
- [x] `lib/steps.ts` + tests: pure derivation (REQ-001, REQ-002).
- [x] `page.tsx`: rail wired, step anchors added, millimetre fields marked optional.
- [x] `orchestrator.ts`: size removed from `missingFields` (REQ-003).
- [x] `globals.css`: studio background, rail styling, sticky panel (REQ-004, REQ-005).
- [x] Intro copy corrected: it told the client that measurements are completed in the panel.
- [x] Specs updated: `consultation` (CONSULT-INV-004 amended), `web`.

## 15. Decision log

- **DEC-001** — CONSULT-INV-004 was amended rather than worked around. The implementation already
  inferred size; the invariant was stale, and leaving it would have misled the next reader about
  what the code does.
- **DEC-002** — Step derivation extracted to a pure module instead of testing the component.
  `vitest` runs in a `node` environment here, and adding a DOM runtime to assert on markup would
  be a larger and less useful change than testing the logic that can actually be wrong.
- **DEC-003** — The panel is made sticky rather than gated by step. Gating would cut its height
  further and is the natural end state, but `page.tsx` is 966 lines and restructuring the form
  around a step machine risks regressions in a working app. Deferred in ADR-0010, with the rail's
  contract designed so gating can be added behind it later.
- **DEC-004** — The background is CSS and an inline SVG grain, not a photograph. No binary asset,
  no licensing question, one request.
