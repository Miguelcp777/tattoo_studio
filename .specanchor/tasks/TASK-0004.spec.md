# Task: Generation provider adapter and the flash render path

## 1. Problem / requested change

Nothing in the system can produce an image. `TattooBrief` exists but has no consumer, so whether
its fields are the right fields is untested (recorded as UNKNOWN in `contracts.spec.md`).

ADR-0001 requires all model access to go through one adapter in `generation`. This task builds
that adapter and the first consumer of a brief: the flash render path.

## 2. Current behavior

- `contracts` defines `TattooBrief` 1.0.0, verified in both runtimes. Evidence: VERIFIED
  (TASK-0002).
- `services/worker` is a shell with settings and a health endpoint. Evidence: VERIFIED (TASK-0001).
- No `generation`, `flash`, `media`, `safety` or `jobs` code exists. Evidence: OBSERVED.
- No hosted-model credentials exist on this machine. Evidence: VERIFIED (user statement,
  2026-09-19; account creation in progress).

## 3. Desired behavior

A brief goes in, a `Design` comes out, through exactly one outbound integration point. Every part
of that path is verifiable offline; the only thing that needs credentials is proving a real
provider returns usable artwork.

## 4. Scope

- `contracts`: `design.schema.json` — the flash output. It crosses module boundaries (flash to
  stencil, mockup and web), so by ADR-0004 it belongs in `contracts`, not in the worker.
- `generation`: the `GenerationProvider` protocol, typed errors, retry policy, a registry
  resolving a provider from configuration, a deterministic `FixtureProvider`, a real fal.ai
  adapter, and a conformance suite every adapter must pass.
- `flash`: prompt construction from a brief, `render_flash`, `refine_flash` with version lineage.
- Ports for the modules that do not exist yet (see section 9).
- `platform`: worker dependency and settings for the provider credential.

## 5. Out of scope

- Any real generation call. Credentials do not exist yet; the live path is verified in a follow-up
  once the key is in place, and is recorded NOT_RUN until then.
- `media`, `safety` and `jobs` implementations. This task defines the ports it needs; TASK-0006
  and TASK-0007 implement them.
- Persistence of designs beyond the in-memory store used by tests.
- The stencil line-art pass (TASK-0005), even though it uses the same adapter.
- Image-conditioned generation (`image_to_image`, `inpaint`). Declared on the protocol and
  **fail-closed**, because the safety gate they depend on does not exist (see REQ-004).

## 9. Design approach

**Dependency inversion for absent modules.** `generation` and `flash` declare dependencies on
`media` and `safety`, which do not exist. Rather than build throwaway versions — which would
pre-empt TASK-0007's security-critical design for EXIF stripping, encryption and cascade deletion
— each consumer defines the narrow port it needs. `media` and `safety` implement those ports
later. Tests supply in-memory doubles.

**Fail-closed by construction, not by check.** `image_to_image` and `inpaint` require a
`SafetyClearance` value. That type has no public constructor: only the safety module can mint one,
and it does not exist. The photo path is therefore unreachable rather than merely guarded, which
is a stronger guarantee than a runtime `if`.

**The fal adapter is written but unproven.** It is implemented against fal's documented HTTP
surface and tested against a mocked transport, so request construction, response normalization,
error mapping and retry behavior are all verified. Whether fal actually returns usable tattoo
flash is a separate question that needs credentials and is explicitly NOT_RUN.

**Prompt construction is pure and offline.** It is the only place FLASH-INV-004 can be enforced,
and a pure function makes adversarial testing cheap.

## 13. Risks and rollback

- fal's API shape is taken from documentation, not observation. Request or response details may be
  wrong, and the mocked-transport tests would not catch it — they assert against my reading of the
  docs. This is the main unverified surface and must be reported as such.
- Prompt quality is not testable offline. The tests prove a prompt is well-formed and free of
  artist names; they say nothing about whether it produces good artwork.
- `refine_flash` semantics may not survive contact with real iteration behavior.

Rollback is `git revert`; nothing consumes flash output yet.

## 15. Decision log

- DEC-001: `Design` is a contract schema rather than a worker-internal type, because it crosses
  into stencil, mockup and eventually web. Applying ADR-0004 to it now is cheaper than retrofitting.
- DEC-002: The fal adapter uses direct HTTP rather than the official SDK. The spec requires
  specific typed errors and a retry policy; an SDK would hide the error surface behind its own,
  and add a dependency for little gain.
- DEC-003: `SafetyClearance` is unconstructable outside the safety module. Fail-closed is a
  property of the type, not of a runtime branch that a future refactor could delete.
- DEC-004: Ports are defined by their consumers, not by the absent modules. This preserves
  ARCH-INV-002 and avoids writing a `media` module that TASK-0007 would immediately replace.

## 18. Final alignment

- **Spec to Code: PARTIAL.** Every requirement has an implementation checked by an
  executed command, but two spec statements are not fully satisfied and claiming ALIGNED
  would overstate it:
  - FLASH-INV-004 (never includes a named living artist) is only partially enforced.
    Mimicry constructions are stripped; bare names are not, because the blocklist belongs
    to `safety`, which does not exist. A test documents the gap.
  - GEN-INV-002 (providers must offer a no-training guarantee) is unverified. fal's data
    terms have not been read. The adapter exists; the eligibility check does not.
- **Code to Spec: ALIGNED.** The reverse pass found four things the code did that the
  specs did not say, each written into a spec or a finding rather than left implicit:
  1. The egress allowlist was vacuous. Nothing imported an HTTP client, so the invariant
     test passed while checking nothing. `generation/http.py` gives the permission
     something to be about, and a test now asserts the allowlist is non-vacuous.
  2. The contracts package shipped no `py.typed`, silently disabling type checking across
     the system's most important boundary. Fixed and recorded.
  3. The brief contract admits unrenderable aspect ratios. The engine now refuses rather
     than clamping; the contract gap is FINDING-0002.
  4. OpenAI's image model offers editing, which is what ADR-0002's blend pass needs. Not
     acted on, recorded as FINDING-0001 for TASK-0008.

**Scope limit on this verdict:** everything is verified offline. Nothing here shows that
fal behaves as documented, and nothing shows the artwork is any good. Both need a
credential, and both are the point of the exercise.
