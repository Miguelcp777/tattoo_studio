# Task: The failed TASK-0054/0055 deploy, and what decides the worker's variables

## 1. Problem / requested change

Deploying TASK-0054 and TASK-0055 failed three times: the worker stopped within eight seconds of
starting. The owner could not delete `TATTOO_TELEMETRY_DSN` in Coolify and asked: "please remove it
from docker compose". Evidence: INTENT.

## 2. Current behavior

`infra/docker-compose.yml` passes `TATTOO_TELEMETRY_DSN: ${TATTOO_TELEMETRY_DSN:-}` to the worker.
Coolify held the variable with the documentation's placeholder (`...@HOST:PUERTO/postgres`).
Evidence: OBSERVED.

## 3. Requirements

- **REQ-001** — The deployed worker starts, keeping events in SQLite until a working Postgres DSN is
  configured. The compose file keeps declaring the variable: it documents the setting, and removing
  it does not stop Coolify from passing it (DEC-001).

## 4. Acceptance criteria

- **AC-001** — The compose worker block passes `TATTOO_TELEMETRY_DSN`, `TATTOO_PRICES` and
  `TATTOO_TELEMETRY_RETENTION_DAYS`, as TASK-0054 left it.
- **AC-002** — The deployed studio starts with the variable deleted in Coolify.

## 5. Decision log

- **DEC-001** — Falsified assumption. Commit `fad0beb` removed the variable from the compose file on
  the assumption that the worker would then not receive it. The next deploy failed the same way.
  Running the new image on the server with the running worker's environment
  (`docker inspect ... .Config.Env`) and a copy of its volume showed the variable was still there:
  Coolify injects every variable it holds into every compose service. `fad0beb`'s changes to the
  compose file, `.env.example` and `test_deployment.py` are reverted.
- **DEC-002** — Once the compose file stopped declaring it, Coolify let the owner delete the
  variable. That, not the compose change, fixed the deploy.

## 6. Evidence ledger

- **ev-001** — 2026-09-30, on the server. Status: OBSERVED (commands run by the owner, output
  pasted). The `fad0beb` worker image with test keys and no volume: `Application startup complete`.
  The same image with the running worker's environment and a copy of the volume:
  `RuntimeError: La telemetría no puede usar Postgres (OperationalError)` from `open_store`.
- **ev-002** — 2026-09-30. Status: OBSERVED (owner's report). With the variable deleted in Coolify
  and the deploy on `HEAD`, the studio deployed and works.
- **ev-003** — 2026-09-30. Status: VERIFIED by execution. After the revert, worker `pytest`
  `app/tests/test_deployment.py` passes, including TASK-0054's assertion that the worker block
  passes the three telemetry settings.
- **NOT_RUN** — Postgres telemetry in production.
