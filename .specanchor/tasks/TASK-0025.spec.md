# Task: FLUX.2 as the skin-background backend

## 1. Problem / requested change

Add BFL FLUX.2 as a configurable image backend. Contributed by another session as a wholesale
replacement for every studio image call; narrowed here to the background alone on live evidence
(ADR-0009). Requested by the owner 2026-09-22.

## 2. Current behavior

- `generation/studio.py` renders every studio image with OpenAI `gpt-image-2`, and also runs
  reference analysis and output moderation. Evidence: OBSERVED.
- No second image vendor is reachable by configuration. Evidence: OBSERVED.

## 3. Desired behavior

`TATTOO_IMAGE_BACKEND=bfl` routes the blank skin background to FLUX.2 on the EU cluster.
Everything else stays on OpenAI. The default remains `openai`, and selecting `bfl` without a
credential fails at startup.

## 4. Scope

`services/worker/generation/bfl_studio.py` (new), `generation/studio.py` (prompt helpers
extracted, OpenAI requests unchanged), `app/settings.py`, `app/studio.py` (`build_provider`),
and the tests for each.

## 5. Out of scope

`contracts`, `mockup`, `stencil`, `web`, the fal adapter, and any change to mockup placement:
ADR-0007's geometric composite is untouched and no body photograph reaches any image model.

## 6. Affected anchors

ADR-0009 (introduces), ADR-0001 (provider selection is configuration — honoured), ADR-0007
(no photograph to a generator — honoured), GEN-INV-001, GEN-INV-002 (still unsatisfied),
SEC-INV-008, PLAT-INV-005.

## 7. Requirements

- **REQ-001** — `TATTOO_IMAGE_BACKEND=bfl` selects `BflStudioProvider`; default stays `openai`.
  Selecting `bfl` without `BFL_API_KEY` fails loudly with values redacted.
- **REQ-002** — FLUX.2 serves the background only, text-only, on `flux-2-pro` by default.
- **REQ-003** — Artwork, edits, reference analysis and output moderation remain on OpenAI under
  either backend, and `image_model` keeps carrying an OpenAI model name.
- **REQ-004** — The EU cluster is the default. Polling and result URLs are followed only over
  HTTPS on `bfl.ai`/`bfl.ml`; the credential never reaches the delivery host and never appears
  in an error.
- **REQ-005** — Moderation statuses and HTTP errors are terminal and explicit. No implicit paid
  retry, no placeholder. Output passes the same size limit and OpenAI output moderation.
- **REQ-006** — OpenAI backend behaviour is unchanged; prompt text is extracted into shared
  helpers without rewording, and no vendor-policing clause is added to any prompt.

## 8. Acceptance criteria

- **AC-001** (REQ-001) — Tests assert the default provider, selection by configuration, and a
  `SettingsError` naming `BFL_API_KEY` with the secret absent from `repr(settings)`.
- **AC-002** (REQ-002) — The background request carries no `input_image*` key and targets
  `/v1/flux-2-pro`.
- **AC-003** (REQ-003) — Tests assert `_artwork` and `edit_artwork` are the inherited OpenAI
  implementations, that `flux` is not reached, and that `image_model == "gpt-image-2"`.
- **AC-004** (REQ-004) — Untrusted base, polling and sample URLs are refused before any request
  or download; the credential is absent from the delivery call and from every error.
- **AC-005** (REQ-005) — Moderation statuses and 401/402/429/500 raise, exactly one submit
  occurs, and the poll times out rather than hanging.
- **AC-006** (REQ-006) — The existing OpenAI provider suite passes unchanged.

## 9. Design approach

See ADR-0009. The adapter subclasses `StudioProvider` and overrides `background` alone, so
every path not named here is the OpenAI path by construction rather than by discipline.

## 10. API / data / UI impact

None. No contract, no schema, no UI change. Configuration only.

## 11. Migration and backward compatibility

The default is unchanged, so an existing deployment behaves identically until
`TATTOO_IMAGE_BACKEND` is set.

## 12. Test plan

Scripted transport, no network and no credential in the suite. Live calls recorded separately
in the evidence ledger and deliberately not automated: they cost money and need a secret.

## 13. Risks and rollback

Two vendors in one path. Rollback is unsetting `TATTOO_IMAGE_BACKEND`, which needs no code
change. The unread BFL retention terms are the real open risk, recorded below.

- [x] `app/settings.py`: backend switch, credential, base URL, background model.
- [x] `app/studio.py`: `build_provider` selects by configuration.

## 15. Decision log

- **DEC-001** — Narrowed from a full backend to the background alone. The contributed change
  was correct as engineering and wrong as product, and only a live call could show that. See
  ADR-0009 for the measurements.
- **DEC-002** — No prompt was rewritten to constrain either model. Two live calls showed
  restriction does not work on FLUX.2, and the owner's instruction was to leave the models
  their creativity. The constraint lives in the routing instead.
- **DEC-003** — `TATTOO_BFL_EDIT_MODEL` removed rather than left unused, so no configuration
  key implies a capability that is not wired.
- **DEC-004** — The contributed `super().__init__(..., image_model=create_model, ...)` set the
  OpenAI image model to `flux-2-pro`. Harmless while every image method was overridden, fatal
  once artwork fell back to OpenAI. Fixed, and pinned by a planted-bug check: reintroducing it
  fails two tests.
- **DEC-005** — A blind `TASK-0024 → TASK-0025` rename during renumbering also rewrote six of
  this repository's own TASK-0024 references. Found by diffing against HEAD and restored.
