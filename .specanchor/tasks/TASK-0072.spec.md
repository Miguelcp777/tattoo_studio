# Task: A design that cannot be made says so plainly

## 1. Problem / requested change

The owner: «si no se puede hacer el tatuaje el mensaje que dé sea claro, no quiero errores 400 ni
similares». Failures reached the client as raised: «El proveedor no ha completado la solicitud
(400)», «FLUX ha superado el tiempo máximo de espera», «El worker rechazó la solicitud», and in the
browser `String(e)` of a parse error. Evidence: INTENT; OBSERVED (screenshot, code).

## 2. Current behavior

- `JobQueue.tick` stored `str(failure)` as the job's error; the router answered `str(error)`.
- The web's worker helpers said «worker» and setup instructions; `page.tsx` parsed every answer as
  JSON and showed `String(e)` on a polling failure. Evidence: OBSERVED.

## 3. Requirements

- **REQ-001** — Worker: `jobs/client_messages.for_client` turns a failure into plain words — known
  technical messages rewritten, timeouts and rate limits «tardando más de lo normal», credits,
  credentials and setup «no disponible», a vendor's content refusal the content message, anything
  else with a status code, vendor, variable, URL or «Error» the generic message — and leaves a
  message written for the client unchanged. It is applied to a failed job's stored error and to
  the router's 422 answers. The panel's job event keeps the original cause.
- **REQ-002** — Web: no message names the worker; `client-errors.ts` words a response by status
  and body (401 session expired, 413 too large, 429 busy, otherwise the server's plain message or
  a generic one), a dropped connection as a connection problem, and a non-JSON answer as empty.
  The studio page, the result viewer and the sign-in page use it. The admin panel keeps technical
  detail, since it is the owner's.

## 4. Acceptance criteria

- **AC-001** — `jobs/tests/test_client_messages.py` and the new `app/tests/test_studio.py` tests:
  technical causes said plainly, client messages unchanged, the panel event keeps «(400)», an
  interrupted job explained without «worker».
- **AC-002** — `lib/client-errors.test.ts`.
