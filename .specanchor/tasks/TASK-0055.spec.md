# Task: The administrator's panel

## 1. Problem / requested change

The owner wants an administrator with access to what other users made, how they interacted, the
tokens spent and time and usage metrics. Choices: body photographs hidden; the role set in
Supabase; designs made durable first (TASK-0047) and events recorded (TASK-0054). Evidence: INTENT.

## 2. Current behavior

No role beyond "signed in"; no view across accounts; events are recorded (TASK-0054) but nothing
reads them. Evidence: OBSERVED.

## 3. Requirements

- **REQ-001** — Only an account whose `app_metadata.role` is `admin` reaches the panel and its
  routes; `user_metadata` never grants it.
- **REQ-002** — The panel shows totals, generation timings, consumption and cost by model, activity
  by day, per-account summaries and recent errors, over 7, 30 or 90 days.
- **REQ-003** — For one account: its conversation, calls, uploads and designs.
- **REQ-004** — A file that shows a body is never shown, and the worker refuses to serve it to the
  administrator whoever owns it.
- **REQ-005** — Every look the administrator takes is recorded under the administrator's id.

## 4. Acceptance criteria

- **AC-001** — Panel routes answer 401 to a stranger and 403 to an ordinary or self-promoted
  account, without reaching the worker; an administrator is let through, as themself.
- **AC-002** — The overview's numbers match the events: counts, success rate, percentiles, tokens,
  priced and unpriced cost, ranking by model, days, people with their address, errors.
- **AC-003** — An account's detail holds only that account's events, and its versions mark the files
  that show a body.
- **AC-004** — The worker serves a design, a stencil and a composite on a generated plate, and
  refuses the body photo, the composite and background on it, and a kept camera photo (403).
- **AC-005** — Overview, account and file views each record an `admin` event with the viewer's id.
- **AC-006** — Live: the panel renders at 1440 px and 375 px without overflow, the detail shows the
  conversation and hides the own-photo view, and the studio header offers "Panel" to the admin.

## 5. Decision log

- **DEC-001** — ADR-0025.
- **DEC-002** — Found by mypy while building: the worker's `/events` route function was named
  `events`, shadowing the event store the admin routes close over. The admin routes would have read
  a function. Renamed `web_events`.
