# Task: A visitor knows how to get in (audit UX-04)

## 1. Problem / requested change

Audit UX-04: the sign-in page said accounts are created by the studio («pídelo») with no way to
ask, and there was no password recovery. Evidence: OBSERVED in `app/entrar/page.tsx`.

## 2. Current behavior

No contact action, no recovery route or page.

## 3. Requirements

- **REQ-001** — «Solicitar acceso» opens an email to `LEGAL_ENTITY.email` with a subject; the
  invitation-only model is kept.
- **REQ-002** — «¿Has olvidado tu contraseña?» → `/recuperar` posts the address to
  `/api/auth/recover`, which asks Supabase for a link back to `/restablecer` and answers the same
  for any address. `/restablecer` reads the token from the fragment, clears it from the address
  bar, and posts a new password (8–128 characters, typed twice) to `/api/auth/password`, which sets
  it with that token. Expired links and short passwords are said plainly.

## 4. Acceptance criteria

- **AC-001** — `app/api/auth/recovery.test.ts`.
- **AC-002** — Live: the three pages render; a request shows the neutral confirmation; a link
  with a token sets the password; without a token the page says the link is invalid.

## 5. Evidence ledger

- **ev-001** — 2026-10-02. Status: VERIFIED by execution. Web `vitest` **163 passed** (159 before);
  `tsc`, ESLint, Prettier clean.
- **ev-002** — 2026-10-02, `node scripts/dev.mjs` with the local Supabase stand-in. Status:
  VERIFIED by execution in the in-app browser: `/entrar` has «Solicitar acceso»
  (`mailto:info@aurevanta.es?subject=Acceso%20a%20Inkcraft`) and «¿Has olvidado tu contraseña?»;
  `/recuperar` with the test address showed the neutral confirmation; `/restablecer` without a

- **NOT_RUN** — A real email through the deployed Supabase (needs its SMTP configuration).
