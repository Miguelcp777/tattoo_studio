# Task: TattooBrief contract and dual-runtime validation

## 1. Problem / requested change

`TattooBrief` is the contract the whole system turns on: the consultation produces it, and the
flash, stencil and mockup engines all consume it. It does not exist. Until it does, no engine has
a defined input and no consultation has a defined output.

ADR-0004 requires one schema as the source of truth for both runtimes, with drift caught by a test
rather than discovered in production. This task builds that, and is the ADR's stated validation.

## 2. Current behavior

- No `contracts/` directory, no schema, no shared types. Evidence status: OBSERVED.
- `apps/web` and `services/worker` exist as shells with no shared payload. Evidence: VERIFIED
  (TASK-0001).
- Tooling confirmed available: ajv 8.20.0, json-schema-to-typescript 16.0.0,
  datamodel-code-generator 0.82.0, jsonschema 4.26.0. Evidence status: VERIFIED
  (registry queries, 2026-09-19).

## 3. Desired behavior

One JSON Schema defines `TattooBrief`. Both runtimes validate against **that same document**, and
a shared fixture corpus proves they agree on every case. Generated types exist for ergonomics but
carry no authority.

## 4. Scope

- `contracts/schemas/tattoo-brief.schema.json` — JSON Schema 2020-12, the source of truth.
- Shared fixture corpus: valid and invalid payloads plus a manifest describing each case.
- TypeScript package `@tattoo/contracts`: ajv validation against the schema, generated types,
  and its half of the parity suite.
- Python package `tattoo-contracts`: `jsonschema` validation against the schema, generated
  pydantic models, and its half of the parity suite.
- Codegen scripts for both targets, with a check that regeneration produces no diff.
- Workspace wiring: pnpm workspace includes `contracts`; the worker depends on the Python package.
- Module map updated for any new path not already covered by `contracts/*`.

## 5. Out of scope

- The other four schemas named in `contracts.spec.md` (`design`, `placement`, `job`, `consent`).
  `TattooBrief` embeds placement and size inline for now; extracting them is a later task.
- Any consumer of the brief. No consultation logic, no engine reads it yet.
- Persistence of briefs.
- Safety screening of brief content, which is `safety`'s job (SAFETY-INV-006), not the schema's.

## 9. Design approach

**The schema document is the validator input in both runtimes.** TypeScript compiles it with
`ajv`; Python runs it through `jsonschema`. Neither translates it. Generated artifacts —
TypeScript interfaces via `json-schema-to-typescript`, pydantic models via
`datamodel-code-generator` — exist for editor support and for FastAPI ergonomics, and are
explicitly **not** the authority.

This matters because the schema uses conditional rules (`if`/`then`) that a generated pydantic
model cannot express. If pydantic were the Python validator, it would silently accept payloads
the schema rejects. Routing validation through the schema in both runtimes removes that class of
divergence entirely rather than testing for it.

**No `format` keyword.** `format` is assertive only when a format checker is wired up, and the
two ecosystems wire it differently, so identical documents could disagree. UUID and timestamp
fields use `pattern` instead, which is assertive everywhere.

**`[0-9]` rather than `\d` in every pattern.** Python's `re` matches Unicode digits with `\d`
while JavaScript's does not, so `\d` would accept Arabic-Indic digits in Python and reject them
in TypeScript. This is precisely the silent drift ADR-0004 exists to prevent, so the patterns
spell out ASCII ranges.

## 13. Risks and rollback

- `datamodel-code-generator` may emit models that fail `mypy --strict`. Mitigation: exclude
  generated Python from strict checking only if unavoidable, and record that as debt rather than
  silently loosening the global mypy configuration.
- `json-schema-to-typescript` may not fully support 2020-12 constructs such as `if`/`then`.
  Since generated types are ergonomics only, a lossy result is tolerable provided it compiles and
  the loss is documented.
- Cross-project Python imports in a uv workspace may need a path source. If that proves awkward,
  the fallback is to vendor the package into the worker, recorded as debt.

Rollback is `git revert`; nothing consumes the contract yet.

## 15. Decision log

- DEC-001: **TypeScript validation uses `ajv` against the schema document, not generated `zod`.**
  ADR-0004 named `zod`. The refinement is that `zod` would be a *translation* of the schema, and a
  translation can diverge; `ajv` consumes the schema itself. Static types still come from the
  schema via `json-schema-to-typescript`, so developer experience is preserved. ADR-0004 is
  amended rather than rewritten, keeping the original reasoning visible.
- DEC-002: Python validation likewise uses `jsonschema` against the document. Generated pydantic
  models are ergonomics, not authority, because they cannot express the schema's conditional rules.
- DEC-003: Generated artifacts are committed rather than produced at build time, which ADR-0004
  left open. Committing them makes drift visible in review, and AC-007 proves they are in sync.
- DEC-004: `placement` and `size` are embedded in `TattooBrief` rather than extracted into their
  own schemas yet. Extracting them before a second consumer exists would be speculative.

  and so reported a difference that meant nothing. The corrected check stages first.
- EV-005: Divergence demonstration (ADR-0004's stated validation). The conditional rule
  forbidding a palette on a black-and-grey brief was deleted from the **Python copy only**. Two
  tests failed: `test_rejects_invalid_fixture[palette-on-black-and-grey]`, because Python now
  accepted what TypeScript still rejected, and
  `test_packaged_schema_is_byte_identical_to_canonical`. Restoring the file returned the suite to
  36 passing. The drift was caught by execution, not asserted in prose.
- EV-006: Coverage. `--baseline` initially **failed** on `.gitattributes` as an unmapped material
  file. Module map corrected; `--baseline` then exit 0 over 76 material files with an empty

- EV-008: Propagation demonstration (ADR-0004's other stated condition). A required field
  `artistNotes` was added to the canonical schema. After regeneration the generated TypeScript
  interface carried `artistNotes: string` and the generated pydantic model carried
  `artistNotes: Annotated[str, Field(max_length=100)]`; all six previously-valid fixtures began
  failing in both runtimes. The schema was restored, verified to contain no trace of the field,
  the packaged copy re-confirmed byte-identical, and all 81 tests returned to passing.
- EV-007: Toolchain friction, recorded because section 13 predicted it. All three risks landed.
  `ajv` strict mode rejected `required` inside an if/then branch (`strictRequired`), relaxed for
  that one lint with reasoning. `datamodel-code-generator` emitted `constr(...)` calls that
  `mypy --strict` rejects; fixed properly with `--use-annotated --field-constraints` rather than
  by excluding generated code from type checking. `jsonschema` needed `types-jsonschema` stubs.

- **Spec to Code: ALIGNED.** Every requirement has an implementation checked by an executed
  command. The one deliberate departure from a spec — `ajv` in place of `zod` — was recorded as
  an ADR-0004 refinement *before* implementing, not justified afterwards.
- **Code to Spec: ALIGNED.** The reverse pass found five things the code did that the specs did
  not say, each written into a spec rather than left implicit:
  1. `platform.spec.md` frontmatter `source_paths` had drifted from `module-map.json`, missing
     six files added in TASK-0001 and this task. The map was right; the spec was stale.
  2. The spec described the pnpm setting as `onlyBuiltDependencies`. pnpm had rewritten the file
     to `allowBuilds` when `approve-builds` ran, so the spec described a key that no longer
     existed. Corrected, with a note that pnpm owns the file's formatting.
  3. CI had grown from three jobs to four; two statements still said three.
  4. ARCH-INV-005 as written permitted a *generated* validator. Implementation showed that is
     unsafe, because generated code cannot express the schema's conditional rules. The invariant
     was tightened, not loosened to match the code.
  5. Line-ending translation was an unstated dependency of the byte-identity assertion.
     `.gitattributes` now makes it explicit rather than leaving the test platform-dependent.

  Nothing was rewritten to legitimise an accidental implementation choice.

**Scope limit on this verdict:** alignment is asserted for `TattooBrief` only. No consumer reads
