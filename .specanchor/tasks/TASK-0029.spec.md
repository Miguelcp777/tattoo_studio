# Task: The master brief and its acceptance gate

## 1. Problem / requested change

Owner request: assemble a master prompt from everything gathered, show it in the chat, and start
generating only once the client accepts. The stated goal is a tattoo that resembles the idea on
the first attempt. Implements ADR-0013. Last of the three tasks.

## 2. Current behavior

- Generation is gated on age, consent, saved preferences and a reference-review checkbox. Nothing
  makes the client confirm the studio understood the request. Evidence: OBSERVED, `page.tsx`
  generate button conditions.
- The technical prompt is assembled in the worker from the brief and is never shown. Evidence:
  OBSERVED, `generation/studio.py::artwork_prompt`.

## 3. Desired behavior

The client reads a summary of what will be tattooed, sees which decisions the studio made for
them, and accepts before anything is generated. Changing anything afterwards withdraws that
acceptance.

## 4. Scope

`packages/consultation/src/agents/master-prompt.ts` and its tests and exports,
`apps/web/src/components/MasterBrief.tsx`, `apps/web/src/app/page.tsx`, `globals.css`.

## 5. Out of scope

Server-side enforcement of the gate; a worker endpoint returning the assembled prompt string;
any change to how a design is generated.

## 6. Affected anchors

ADR-0013 (implements), ADR-0011 (a size that fills the zone is a studio proposal), ADR-0012 (the
chosen catalogue variant is the most specific thing said about style), WEB-INV-001.

## 7. Requirements

- **REQ-001** — A master brief is derived from the same slots and references that are sent for
  generation, in a pure function testable without a DOM.
- **REQ-002** — Decisions the studio made rather than the client are marked as proposals.
- **REQ-003** — An incomplete brief names what is missing and cannot be accepted.
- **REQ-004** — Acceptance is recorded as the content accepted, so any later change withdraws it.
- **REQ-005** — Generation is gated on acceptance alongside the existing conditions.
- **REQ-006** — The technical disclosure is the brief itself, collapsible, not the assembled
  prompt string.

## 8. Acceptance criteria

- **AC-001** (REQ-001) — `buildMasterPrompt` is unit-tested over a complete brief and partial ones.
- **AC-002** (REQ-002) — A size exactly filling the zone span is marked proposed; a size the
  client chose is not; the technical linework weight is marked proposed.
- **AC-003** (REQ-003) — Missing subject, style, zone and colour are each named. A missing size is
  not reported before the zone is known, since a size without a zone is meaningless (ADR-0011).
- **AC-004** (REQ-004) — Acceptance is derived from a signature of the presented lines, so a
  changed line cannot leave a stale acceptance behind. Verified by construction and by review of
  the state derivation.
- **AC-005** (REQ-005) — The generate button's disabled condition includes acceptance.
- **AC-006** (REQ-006) — The panel renders the brief JSON behind a disclosure, and the client
  bundle builds.

## 9. Design approach

See ADR-0013. The only decision worth restating is that acceptance is stored as *what* was
accepted rather than *that* it was accepted, which makes staleness impossible to get wrong: there
is no effect to forget to run and no flag to forget to clear.

## 10. API / data / UI impact

UI only. No contract, schema or route change.

## 11. Migration and backward compatibility

None. An existing session simply gains a step before generation.

## 12. Test plan

Unit tests over the projection. The gate itself is a rendering condition, verified by reading the
derivation and by the build; there is no DOM test environment in this project.

## 13. Risks and rollback

The gate is presentational. A caller bypassing the interface can still submit a job, so this is a
usability control and not a security one. Rollback is removing the acceptance condition.

## 15. Decision log

- **DEC-001** — The literal prompt string is not shown. Reproducing it in TypeScript would be the
  drift this project has already had to fix twice, and the real string embeds the anti-injection
  framing, which is neither useful to a client nor wise to publish. The brief is shown instead:
  it is what the studio actually receives.
- **DEC-002** — Acceptance is a stored signature, not a boolean. The first attempt used a boolean
  plus a ref reconciled during render, which mutates state while rendering; deriving acceptance
  from a comparison removes the problem rather than managing it.
- **DEC-003** — The gate is not enforced server-side. Recorded as a limitation rather than
  implied to be protection, and left in scope for a later task.
