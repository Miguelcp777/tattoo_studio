# Task: Search the web for an essential reference, through Brave

## 1. Problem / requested change

"¿No se puede buscar imágenes de Google?" — then, offered Brave (Google's API is closed to new
customers), "hazlo con Brave". Evidence: INTENT.

## 2. Current behavior

With a judge, a query the licensed sources missed fell back to `openWebFallback`, which no deployed
configuration provided and which bypassed the judge. Evidence: OBSERVED.

## 3. Requirements

- **REQ-001** — Only an essential reference the licensed sources lacked is searched on the web.
- **REQ-002** — Web candidates face the judge; refused ones are not kept.
- **REQ-003** — Only Brave-proxied thumbnails are used and downloaded; results are labelled with the
  author's rights and their page; searches are metered.
- **REQ-004** — Enabled only with the switch, the key and the Claude scout.
- **REQ-005** — The privacy policy names Brave; the image-consent version is bumped.

## 4. Acceptance criteria

- **AC-001** — `brave-search.test.ts`: endpoint, `q`, `safesearch=strict`, key header; only Brave
  thumbnails kept, label stripped, licence and page set; usage reported, a 429 reported as an error.
- **AC-002** — `brave-search.test.ts`: the generic query never reaches the web, the essential one
  does and is judged; a refusal keeps nothing.
- **AC-003** — `reference-bytes.test.ts`: a Brave thumbnail downloads, the same with a query does
  not. `live-agents.test.ts`: enabled only with all three settings.

## 5. Evidence ledger

- **ev-001** — 2026-10-01. Status: VERIFIED by execution. Consultation `vitest` **107 passed** (102
  before); web `vitest` **132 passed** (130 before); `tsc` clean in both; ESLint clean; worker
  `test_deployment.py` 11 passed.
- **NOT_RUN** — A real Brave request (no key in development), so the response shape is taken from

  download refuses redirects) is unverified until the key is set on the deployed studio.
