# Task: Deployment configuration for one self-hosted node

## 1. Problem / requested change

The owner asked to deploy the app, first naming Netlify, then said they have a Proxmox host. The
camera try-on (TASK-0042) cannot be tested at all without HTTPS. Evidence: INTENT.

## 2. Current behavior

- `infra/*` is declared in `module-map.json` but empty; `platform.spec.md` records "no deployment
  configuration exists" and lists hosting and region as UNKNOWN. Evidence: OBSERVED.
- `scripts/dev.mjs` is the only way to run the system, and it runs both halves on `http://`
  localhost. Evidence: OBSERVED.

## 3. Desired behavior

One command on a fresh VM brings up the studio behind a real certificate, with the worker
unreachable from outside and state on a volume.

## 7. Requirements

- **REQ-001** — Container images for the web app and the worker, built from this repository,
  reproducing the wiring the test suite exercises.
- **REQ-002** — A compose file where only the proxy publishes ports, the worker is a single
  replica, and state lives on a named volume.
- **REQ-003** — TLS through a DNS-01 challenge, so no inbound port is needed for issuance and a
  private hostname is supported.
- **REQ-004** — A configuration template that names every variable and holds no secret, and an
  `infra/.env` that git ignores.
- **REQ-005** — A runbook that leads the owner from a blank VM to a working camera try-on, and
  states the exposure risk of running without authentication **before** any step.

## 8. Acceptance criteria

- **AC-001** — `infra/.env` is ignored by git and `infra/.env.example` is not.
- **AC-002** — The compose file parses; `caddy` is the only service publishing ports; `worker`
  publishes none.
- **AC-003** — Every build command the Dockerfiles run resolves in this repository.
- **AC-004** — The worker image sets `TATTOO_DATA_DIR` onto the mounted volume, and the compose file
  pins the worker to one replica with the reason recorded.
- **AC-005** — The certificate configuration expresses a DNS-01 challenge and the proxy image
  compiles a DNS module.
- **AC-006** — The runbook states the no-authentication exposure before its first step.
- **AC-007** — The committed configuration template holds no credential-shaped value.

Deliberately **not** an acceptance criterion of this task: that the stack runs on the VM. That is
the owner's step on their own hardware, and claiming it here would be claiming something unrun.

## 15. Decision log

- **DEC-001** — ADR-0020: one self-hosted node; Netlify rejected on three independent grounds
  (no persistent disk for the worker, in-memory sessions across serverless instances, US region
  against the product's own residency claim).
- **DEC-002** — Supabase is **not** part of this task. The owner asked for "Supabase for
  everything"; replacing SQLite and the encrypted file store touches encryption at rest, retention
  and cascade deletion, all of which carry invariants. Doing that in the same step as the first
  deployment would make a failure impossible to attribute. It follows as its own task.
- **DEC-003** — The web image is not a Next `standalone` build. The app is a pnpm workspace with a
  native dependency (`sharp`); a traced bundle is a production-only failure mode. Size traded for
  the same wiring the tests run against.
- **DEC-004** — The contracts are regenerated during the image build rather than trusted from the
  checkout, so a stale generated schema cannot ship as a silent contract mismatch.
- **DEC-005** — In-memory sessions are kept. On one node with one web process they work; the
  restart failure mode is documented in the runbook instead of being engineered away.
