# Task: Hello, and a way out

## 1. Problem / requested change

The owner, with the login deployed: "me faltan: un botón de log out, un mensaje de Hello
'usuario'". Evidence: INTENT.

## 2. Current behavior

- The studio shows no sign of who is signed in and offers no way to sign out. `DELETE /api/auth`
  exists but nothing calls it. Evidence: OBSERVED.
- That route only clears the browser's cookies; the refresh token stays valid at Supabase for its
  thirty days. Evidence: OBSERVED (`api/auth/route.ts`).
- **Found while doing this:** the consultation in progress is keyed by the browser's `inkcraft`
  cookie and nothing else. Since TASK-0046 stored work follows the account, but the conversation
  did not: a second person signing in on the same browser was handed the first person's
  conversation. Evidence: OBSERVED, and reproduced by the test below against the previous code.

## 3. Requirements

- **REQ-001** — The studio greets the signed-in person by name: the name set on the account in
  Supabase if there is one, otherwise the part of the address before the @. Never the whole
  address.
- **REQ-002** — A visible "Salir" signs out: the session is ended at Supabase, the tokens and the
  consultation cookie are cleared, and the browser lands on the sign-in page.
- **REQ-003** — Signing out cannot fail because Supabase is unreachable.
- **REQ-004** — A consultation belongs to the account that started it. Another account on the same
  browser never sees it, and starting to talk gives them a new one.

## 4. Acceptance criteria

- **AC-001** — `GET /api/auth` returns a display name from `user_metadata` (`name`, `full_name` or
  `display_name`), else the address's local part; the account id is not returned.
- **AC-002** — `DELETE /api/auth` calls Supabase `POST /auth/v1/logout?scope=local` with the access
  token and clears `inkcraft_at`, `inkcraft_rt` and `inkcraft`.
- **AC-003** — With Supabase unreachable, or with no session at all, sign-out still answers 200.
- **AC-004** — Account B with account A's consultation cookie reads no consultation, gets a new one
  when it talks, and A's is untouched.
- **AC-005** — Live: the greeting and "Salir" render in the header at 1440 px and 375 px without
  overflow, and "Salir" ends on `/entrar` with no way back to `/` without signing in.

## 5. Decision log

- **DEC-001** — `scope=local` ends this session, not every session the account has. Signing out of
  a phone should not sign the laptop out.
- **DEC-002** — A consultation from another account is treated as absent rather than refused with
  an error. The person in front of the browser did nothing wrong; they should simply start clean.
- **DEC-003** — A consultation created before this change has no owner and is claimed by the first
  account that uses it. Consultations live in memory, so any deploy empties them anyway.
