# Task: Put the Claude architect and scout on the live consultation route (resolves FINDING-0004)

## 1. Problem / requested change

TASK-0032 delivered the Claude prompt architect (`ClaudeConsultationProvider`, Opus 5.5) and the
Claude scout planner (`ClaudeScoutQueryPlanner`, Sonnet 5) as tested capabilities, but the live web
route never uses them (FINDING-0004). The user asked for them to work in the real consultation
(2026-09-26).

## 2. Current behavior

- `apps/web/src/lib/studio-server.ts` builds `new OrchestratorAgent()`; slots come only from the
  regex `extractPreferences`; the scout is built without `ScoutOptions`. OBSERVED.
- `CONSULTATION_SYSTEM_PROMPT` lists 10 styles although the contract vocabulary has 16 since
  TASK-0027, and its JSON example carries a filled-in `mimicryDetected` object a model may echo.
  OBSERVED.

## 3. Desired behavior

- `OrchestratorAgent` accepts an optional `ConsultationProvider` (the architect). On a chat turn
  with text it sends the conversation (text only) and merges the architect's slots into the
  regex-extracted ones.
- Merge precedence: explicit client statements and earlier decisions win; the architect fills
  gaps (subject elements, style, body part, orientation, colour, constraints). Technical proposals
  (linework, shading) may replace only their untouched defaults. **Size and side are never taken
  from the architect** (ADR-0010/0011; side added after the live run, EV-010). Every architect value is validated against the contract vocabulary;
  anything else is dropped (CONSULT-INV-003).
- A genuine mimicry flag from the architect (non-empty artist name) is handled like the regex
  mimicry branch (PROD-INV-004).
- Any architect failure falls back to the deterministic path; the conversation never breaks.
- The web composition root opts in explicitly: `TATTOO_CONSULTATION_BACKEND=claude|openai` enables
  the architect; `TATTOO_SCOUT_PLANNER=claude` enables the Sonnet planner. A credential alone
  enables nothing, so a developer key cannot make tests call a paid API.
- The shared prompt lists all 16 styles and asks for `mimicryDetected: null` unless a named living
  artist is requested.

## 4. Scope

`packages/consultation` (orchestrator, new `agents/architect.ts`, shared prompt, provider timeout)
and `apps/web/src/lib/studio-server.ts` (composition). Specs: consultation, web, FINDING-0004.

## 5. Out of scope

- Sending reference images to the architect (new egress of user content; not requested).
- Marking architect-proposed lines as "proposed" in the master brief (needs slot provenance).
- An open-web search provider and a TS candidate screen implementation.

## 6. Affected anchors

CONSULT-INV-001..005, ADR-0010, ADR-0011, ADR-0013 (the client still accepts the master brief
before generation, which is where architect proposals are reviewed), ADR-0015, WEB-INV-001.

## 7. Requirements

- TASK-0033/REQ-001: `OrchestratorAgent` optionally consults a `ConsultationProvider` on chat turns
  with text and merges its slots with the stated precedence.
- TASK-0033/REQ-002: Architect values outside the contract vocabulary or bounds are dropped;
  size is never adopted from the architect.
- TASK-0033/REQ-003: Architect failure falls back to deterministic extraction with no user-visible
  error.
- TASK-0033/REQ-004: A non-empty architect mimicry flag declines imitation like the regex branch.
- TASK-0033/REQ-005: The web composition root enables the architect and scout planner only by
  explicit configuration.
- TASK-0033/REQ-006: The shared prompt matches the 16-style contract vocabulary and does not
  invite a placeholder mimicry object.

## 8. Acceptance criteria

- TASK-0033/AC-001: With a fake architect, a vague idea gains style, zone and colour; the client's
  own subject text is unchanged; no question is asked for fields the architect filled.
- TASK-0033/AC-002: Explicit regex values (style, zone, side, colour) win over conflicting
  architect values; an architect size is ignored.
- TASK-0033/AC-003: Invalid architect values (unknown style, zone, colour mode, weight; oversized
  elements) are not adopted.
- TASK-0033/AC-004: A throwing architect yields the same slots as no architect.
- TASK-0033/AC-005: A genuine mimicry flag produces the decline message and no brief; an empty or
  placeholder flag does not.
- TASK-0033/AC-006: The architect is not called on panel actions without text; the turns it
  receives start with the user, alternate roles and end with the current input.
- TASK-0033/AC-007: `liveAgentConfig` enables agents only for explicit settings; a key alone does
  not.
- TASK-0033/AC-008: All existing consultation and web tests pass; lint and typecheck clean.

## 9. Design approach

New `agents/architect.ts` holds turn building, sanitizing and merging so the orchestrator stays
readable. The orchestrator computes regex slots first, then consults the architect, then applies
technical defaults. `studio-server.ts` exports `liveAgentConfig(env)` and `buildOrchestrator(env)`.

## 12. Test plan

`tests/architect.test.ts` (consultation) for AC-001..006; `studio-server.test.ts` (web) for AC-007;
full `pnpm test`, `pnpm lint`, `pnpm typecheck` for AC-008.

## 13. Risks and rollback

- A wrong architect guess (e.g. a side the client never stated) is visible in the master brief the
  client must accept (ADR-0013). Residual risk: those lines are not yet flagged as proposals.
- Latency/cost per chat turn: bounded by a request timeout; opt-in only.
- Rollback: unset `TATTOO_CONSULTATION_BACKEND` / `TATTOO_SCOUT_PLANNER`; behaviour reverts to the
  deterministic route with no code change.
